# GitHub Copilot とスライドを作成する

> English version: [English](../ai-assisted-authoring.md)

MarkdStage は、GitHub Copilot App をオーサリングパートナーとして利用できるように設計されています。
Markdown を信頼できる唯一の情報源として維持しながら、同じチャットセッション内でスライドを作成・改善するために
必要な構文リファレンス、スキーマ、表示中のデッキ状態、出力診断を MarkdStage が Copilot へ提供します。

![Markdown デッキを開いた MarkdStage Canvas Extension](../images/canvas-main.png)

## Copilot が利用できる情報

MarkdStage は、Copilot がスクリーンショットだけからプレゼンテーション形式を推測するのではなく、
目的に応じた情報を利用できるようにします。

| 情報 | オーサリングでの用途 |
| --- | --- |
| スライド形式のガイダンス | スライド区切り、フロントマター、レイアウト、コンテンツサイズ、スピーカーノート、対応する Markdown を説明 |
| テーマのガイダンス | 組み込みテーマと選択方法を説明 |
| カスタムテーマのガイダンスとスキーマ | 対応する CSS カスタムプロパティ、メタデータ、アセット、セキュリティ制約を定義 |
| Architecture DSL のガイダンスとスキーマ | 要素、レイアウト、アイコン、コネクター、上限、検証規則を定義 |
| 現在のデッキ内容 | 表示中の Markdown を修正対象として維持 |
| Architecture の検証 | 対象スライド、図ブロック、JSON パス、修正方法を含む構造化エラーを返す |
| 固定 16:9 レイアウト診断 | クリップされるページを特定し、はみ出し量と関連要素を報告 |
| 対象スライドの画像 | 視覚的な確認が必要なページや問題のあるページを 1280x720 の画像として生成 |

Canvas を開いている間、アクティブなデッキと Architecture DSL は GitHub Copilot App の
コンテキストで利用できます。追加情報が必要な場合、Copilot は上記の目的別リファレンスと診断を取得できます。

`markdstage_guide` ツールは、`slide-format`、`themes`、`custom-themes`、`theme-schema`、
`architecture-dsl`、`architecture-schema` などのトピックごとにオーサリング情報を提供します。
Canvas のアクションは Architecture の検証、固定レイアウト診断、選択したスライドの画像生成を提供します。

これらの機能により、Copilot は最初に Markdown の文法と構造化された測定値を使用し、
視覚的な判断が必要な問題だけを画像で確認できます。

目的と要件を具体的に指定すると、変更内容を Markdown ソースと Canvas で確認可能な状態に保ちながら、
作成、表示、確認の大部分をチャットから進められます。

記録済みの一連の例は、
[ハンズオン: GitHub Copilot でデッキを作成する](copilot-hands-on.md)を参照してください。

## 推奨オーサリングワークフロー

1. **ソースと目的を指定します。** ソースファイルまたはメモ、対象者、プレゼンテーションの目的、
   希望するテーマ、おおよその長さを伝えます。
2. **Markdown デッキ全体を作成します。** Copilot は MarkdStage のガイダンスを参照し、
   スライド断片を作成して、デッキ全体を Canvas で開けます。
3. **表示結果を確認します。** アクティブなデッキで、構成、情報量、図、スピーカーノート、
   用語を確認します。
4. **構造化コンテンツを検証します。** 視覚的に確認する前に、Architecture DSL のスキーマ、
   参照、配置エラーを検出できます。
5. **固定 16:9 出力を検査します。** レイアウト診断が PDF 相当の出力でクリップされるページを特定し、
   修正に利用できる測定値を提供します。
6. **視覚的な分析が必要なページだけを画像化します。** デッキ全体の画像を生成せず、
   対象の PNG からバランス、間隔、図の見え方を Copilot が確認できます。
7. **修正と確認を繰り返します。** Copilot が Markdown を更新してデッキを再読み込みし、
   プレゼンテーションまたはエクスポートの準備が整うまで対象ページを再検査します。

```text
ソースと目的
  → MarkdStage のガイダンスとスキーマ
  → Markdown デッキ
  → Canvas での表示
  → 構造化検証と 16:9 診断
  → 必要なスライドだけを画像化
  → Markdown を修正
  → プレゼンテーションまたは PDF
```

## 効果的な依頼を記述する

デッキの構成と視覚的な方向性に影響する情報を含めます。

- ソース資料または Markdown のパス
- 対象者とプレゼンテーションの目的
- 想定時間またはスライド枚数
- 希望するテーマまたはブランド上の制約
- 必要なセクション、図、ノート、用語
- 固定 16:9 PDF 出力の検証が必要かどうか

### ソース資料からデッキを作成する

```text
proposal.md から8枚のアーキテクチャレビュー資料を作成してください。
Microsoft テーマを使用し、スピーカーノートを追加して、システム概要には Architecture DSL を使用してください。
デッキ全体を MarkdStage で開き、エクスポート前に 16:9 のクリッピングを修正してください。
```

### 既存のデッキを修正する

```text
技術者向けの資料として slides.md をレビューしてください。
セクションの順序とすべてのコード例を維持したまま、情報量の多いスライドを整理してください。
修正後にデッキ全体を開き直し、固定 16:9 レイアウトを確認してください。
```

### 特定の図を改善する

```text
サービス境界とデータフローを追いやすくするため、4枚目の Architecture DSL を更新してください。
図を検証してスライドを表示し、ラベルやコネクターが重なる場合は配置を修正してください。
```

### 出力上の問題を調査する

```text
このデッキを PDF 相当のクリッピングについて検査してください。
対象の Markdown ページを修正し、視覚的な確認が引き続き必要なページだけを画像化してください。
```

## 検証機能を理解する

### Architecture の検証（`get_architecture_errors`）

Architecture の検証は、デッキ全体または選択したスライドの機械可読なエラーを返します。
Copilot は対象ページ、Architecture ブロック、JSON パス、修正方法を利用し、
試行錯誤だけに頼らずソースを更新できます。

### 固定 16:9 の検査（`inspect_layout`）

固定レイアウトの検査は PDF 相当の 1280x720 サーフェスを表示し、はみ出すページを報告します。
診断には縦方向と横方向のはみ出し量、および問題付近の要素を限定した一覧が含まれます。

![縦方向のクリッピング警告を表示した固定 16:9 プレビュー](../images/canvas-layout-warning.png)

この診断は、コンテンツがページ内に収まるかを確認するためのものです。
内容の明確さ、情報の階層、視覚的なバランスに対する編集者の確認を置き換えるものではありません。

### 対象スライドの画像生成（`capture_slides`）

スライド画像の生成では、明示的に選択したページを PNG ファイルとして出力します。
ページを指定しない場合、MarkdStage は先にデッキを検査し、クリッピング問題があるページだけを
画像化できます。生成されたファイルはワークスペース内に保存され、同じセッションで Copilot が確認できます。

画像はすべてのページを確認する既定の方法ではなく、構造化診断の後に使用してください。

## 作成者による確認

AI を利用したオーサリングは、作成、表示、確認のサイクルを短縮しますが、
最終的なデッキに対する責任は作成者にあります。

- Markdown ソース内の事実、名称、コード、機密情報を確認してください。
- スピーカーノートに発表者向けとして適切な内容だけが含まれることを確認してください。
- 図はスキーマの有効性だけでなく、技術的な意味も確認してください。
- 配布前にエクスポートした PDF のすべてのページを確認してください。
- プロジェクトの一部として使用するデッキは、ソースファイルをバージョン管理してください。

AI 向けのオーサリング機能と検証機能は Canvas Extension が提供します。
MarkdStage Desktop は既存デッキのプレゼンテーションに特化しています。
